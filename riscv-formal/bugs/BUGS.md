## Why these checks catch these faults

- **TB001/002** corrupt the *actual* register write while RVFI keeps
  reporting the intended address/value, so the architectural register
  diverges from RVFI's claim — the `reg` consistency proof (compare what
  RVFI says was written to `xN` against what is later read) fails.
- **TB003/004** corrupt the RVFI *trace* (`rd_addr`/`rd_wdata`); every
  per-instruction check compares the trace against the decoded ISA
  expectation, so e.g. `insn_addi` fails immediately.
- **TB005** corrupts the reported next-PC; the `pc_fwd` forward-progress
  proof (and the per-instruction next-PC check) fails.

Each counterexample is a concrete VCD trace under the matching
`work/.../picorv32/testbugNNN/<check>/engine_0/` directory; disassemble
the offending instruction with the core's `disasm.py` if desired.
